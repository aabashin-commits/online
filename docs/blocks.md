Плейсхолдеру тот же кегль (зум считает по font-size поля, но иначе плейсхолдер был бы мельче текста). ⚠️ У `.form-modal` обязателен `align-items: flex-start`: с базовым центрированием форма выше экрана уходит верхом в минус и **крестик становится недоступен** (на 360×691 окно вставало на `top: -44`). ⚠️ **Крестик на телефоне — `absolute`** (правка 22.07.2026): 21.07 по жалобе «не видно крестик» его переводили на `position: fixed`, чтобы не уезжал при прокрутке формы, — **на реальном айфоне это не помогло**, вернули `absolute` (положение из макета), а доступность держит явная прокрутка формы (`overflow-y: auto` + `-webkit-overflow-scrolling: touch` в мобильном блоке; замер в WebKit: на 360×600 форма скроллится на 179px, крестик при возврате наверх снова на 5/6). ⚠️ Вероятная причина «фикс не сработал» — **кеш CSS на телефоне**: Safari держит файл по URL очень цепко. Поэтому у `header.css` и `form.css` в `index.html` появился параметр `?v=` — **при каждой заливке изменённого CSS номер поднимать**. ⚠️ **31.07.2026 то же заведено и для JS: `js/header.js?v=2`.** Раньше версии были только у CSS, и после заливки выпадашек браузер продолжал крутить старый закешированный `header.js` — кнопки в шапке были полностью мёртвыми. **Правишь JS-файл — поднимай его `?v=` в `index.html`.** Плюс подложка `rgba(255,255,255,.18)` — белый крест 2px попадал на светлый блик окна (радиальная подсветка в 88% 8%) и терялся. На десктопе всё по-старому: `absolute`, 30/30, без подложки. ⚠️ Там же на телефоне: `.form-modal` получает **`height: 100dvh`** (в iOS Safari `position: fixed; inset: 0` растягивается на «развёрнутый» экран, края уходят под панели браузера; старым Safari <15.4 свойство неизвестно — у них отработает `inset: 0`), а поля окна — **`env(safe-area-inset-top/bottom)`** поверх макетных 89/40, иначе заголовок лезет под чёлку, а кнопка «отправить» — под полосу жеста |
