⚠️ **Это онлайн-версия лендинга.** Она сделана копией офлайн-сайта
(`Lendosi/скул офлайн/`, бывшая папка `school/`) 12.08.2026 и дальше живёт
самостоятельно: общих файлов у папок нет, правки друг в друга не переносятся.
Чем отличается — см. раздел «Онлайн-версия» ниже.

Одностраничный лендинг школы. Эталон дизайна — макет `1920.png` (десктоп 1920px) и материалы в папке `фото тз/`. План работ и статус вводных от клиента — в `PLAN.md`.

## ⚠️ Правила этого проекта переопределяют правила репозитория

Общий `Lendosi/CLAUDE.md` (Tailwind, один файл, минимум токенов) здесь **НЕ действует**. Для этой папки правила такие:

1. **Всегда подробно рассказывать, что делаешь:** перед каждым шагом (команда, правка файла, скриншот, диагностика) — объяснять простым языком, что это за действие, зачем оно нужно и что даст. Особенно для вспомогательных/технических команд (обработка картинок, установка утилит, отладка) — их назначение неочевидно, проговаривать обязательно.
2. **Стек:** чистые HTML + CSS + vanilla JS. Никаких фреймворков (React/Vue/Nuxt), сборщиков, npm и Tailwind. Никаких CDN-библиотек, кроме случая, если клиент явно попросит (аналитика, карты).
3. **Файлы по блокам:** у каждого блока страницы свой CSS-файл; у блоков с поведением — свой JS-файл. Всё подключается напрямую в `index.html`: CSS через `<link>`, JS через `<script defer>`. Без импортов, без сборки.
4. **Кастомный CSS писать можно и нужно** — это основной инструмент стилизации.
5. Ответы и код — без ограничений на «минимум токенов»: приоритет — точное соответствие макету.

### Вырезка hero `kid-online.webp` (13.08.2026)

Заменила пару вырезок офлайн-версии: теперь в hero **одна** картинка — девочка
с ноутбуком, и в неё **вшиты четыре плашки** («удобство», «живые занятия и в записи»,
«гибкость», «гос аттестат»). Отдельными элементами плашек нет, текст в них
из вёрстки не правится — только перерисовкой картинки.

⚠️ **Доли ширины на планшете и телефоне пересчитаны** (`min(70%, 460px)` на ≤1024
и `86%` на ≤767 вместо прежних `min(48%, 320px)` и `50%`): старые значения делили
ширину между ДВУМЯ вырезками, и одна картинка выходила вдвое мельче нужного.

⚠️ **`.hero__kids` подняты на `bottom: 30px`, а не 0.** Инфо-карточки наезжают
на низ панели на 110px, и при `bottom: 0` нижняя плашка «гос аттестат» (её пилюля
кончается на ~87% высоты вырезки = 96px над низом панели) уходила под них
и обрезалась. Подъём выводит плашку из зоны наезда с запасом ~16px, при этом
прямой срез картинки снизу остаётся спрятан под карточками — иначе была бы видна
линия обрезки.

⚠️ **У исходника была «грязная» альфа:** внутри 253 вместо 255, а снаружи 1–3
вместо 0, и RGB под этими пикселями чёрный — на синем фоне это давало тёмную дымку
по краям, а при ресайзе чёрный затекал в контур. Лечится растяжением альфы
(≤6 → 0, ≥250 → 255), выбросом крапин-артефактов (было 4 штуки) и заливкой RGB
под прозрачным цветом обводки (#FDF8E9). **Пришлют замену — прогнать те же шаги.**

**Как сделана вырезка в блоке «О нас»** (исходник клиента — PNG 4092×6148 БЕЗ альфы,
фон чёрный, обводка обрезана верхним краем кадра: на y=0 уже крем, волосы
с y=72). Скрипт-однодневка на numpy + scipy.ndimage + Pillow:
1. силуэт = `luma > 30` + `binary_fill_holes`;
2. **старая обводка снимается по цвету** (`R>230, G>205, B>180, 18<R−B<70, 6<R−G<40`) —
   белая футболка и кроссовки под условие `R−B>18` не попадают, а кремовые блики
   внутри фигуры становятся дырками и возвращаются заливкой;
3. холст добивается сверху, обводка рисуется заново по расстоянию до силуэта
   (`distance_transform_edt`, ширина замерена по 98-му процентилю = **93.8px**) —
   над головой шапочка получается круглой сама собой;
4. экспорт 1100×2800 WebP q82, 186 КБ.
Пересобирать вырезку → повторить эти шаги, иначе обводка снова будет рваной.

## 🎬 Видео на сайте (добавлено 31.07.2026)

Два набора роликов, оба лежат в `assets/video/` и заливаются на прод обычными файлами
(180 МБ суммарно): **15 отзывов** (`reviews/`) в блоке 14 и **3 обзорных** (`school/`)
в карточке блока 7. Исходники клиента — в папках `otzivi/` и `obzor/` в корне,
**обе в игноре `sftp.json`** (там ~510 МБ, на прод им нельзя).

⚠️ **Присланные ролики нельзя отдавать браузеру как есть — это выгрузки с YouTube.**
Аудиодорожка везде **Opus**, а у 6 отзывов видео — **VP9**, и всё это в контейнере MP4.
Проверено в WebKit через `canPlayType`: `avc1+opus` → **пусто**, `vp09+opus` → **пусто**,
`avc1+mp4a.40.2` → `probably`. То есть в Safari (и macOS, и iOS) исходники либо не
открылись бы вовсе, либо шли без звука. Chrome это скрывает — он играет и то, и другое,
поэтому проверять видео **только в Chrome бессмысленно**.

Рецепт перекодирования (ffmpeg 6.0 из npm-пакета `ffmpeg-static`; `brew` в системе нет,
ставился во временную папку, в проект не попал):

```
ffmpeg -i IN -vf "scale=-2:720" -c:v libx264 -preset medium -crf 26 \
  -profile:v high -pix_fmt yuv420p -c:a aac -b:a 96k -ac 2 \
  -movflags +faststart OUT.mp4
```

- **720p, а не 1080p** — лайтбокс максимум 1100px шириной, выше смысла нет.
- **`-movflags +faststart` обязателен**: иначе moov-атом остаётся в конце файла и
  браузер начинает проигрывание только после полной загрузки.
- Постеры: кадр из ролика → PNG через ffmpeg → WebP через Pillow. **Через сам ffmpeg
  WebP не гнать** — libwebp может отсутствовать в статической сборке.

⚠️ **Постер «Средняя и старшая школа» — не кадр из ролика,** а отдельная картинка от клиента
(групповое фото учеников и педагогов, 31.07.2026). Она детальнее видеокадра, поэтому весит
150 КБ против ~50 КБ у остальных — качество WebP снижено до 68 (на 60/68/75 разницы на лицах
при 1:1 не видно, проверено кропом). ℹ️ Файл сгенерирован/обработан нейросетью — если это
не реальный снимок школы, стоит помнить, что посетитель прочтёт превью как документальное фото.

⚠️ **Имена файлов постеров при замене не меняются, поэтому в `about.js` есть `POSTER_V`** —
версия в query-параметре (`?v=2`). Safari держит картинку по URL очень цепко и без параметра
продолжал бы показывать старую. **Меняете кадр — поднимите `POSTER_V`** (и `?v=` у `about.js`
в `index.html`, иначе браузер не увидит и сам новый JS).

В начале и конце роликов стоят заставки-логотипы, встречаются кадры-перебивки и зелёные
вспышки переходов, а нижняя плашка с титрами при обрезке 16:9 → 1.417 режется по краям
и текст выходит рваным. У `dotsenko-zoya` плашка висит весь ролик (он всего 15с), поэтому
там обрезка **от левого края**, а не по центру — так плашка остаётся целой.

исходников по подстроке без `unicodedata.normalize('NFC', …)` не находит ничего с й/ё,
хотя имена выглядят одинаково. На этом уже спотыкались при сопоставлении слагов.

## 🫧 Резиновая вёрстка — базовая модель (проход 21.07.2026)

Страница **резиновая**: между контрольными ширинами ничего не «прыгает».
Раньше было три отдельных состояния (1920 / 1600-1200 / 360), сшитых 12 порогами;
теперь размеры интерполируются, а медиазапросы остались только там, где макет
реально **перестраивает раскладку**.

**Три правила, которым следует каждый блок:**
1. **Текст — `clamp()`** между кеглями макета (1200 → 1600 → 1920). Пропорционально
   ширине кегль не масштабируем никогда: при чистой пропорции наборный текст
   на 1100 падает до 10px.
2. **Раскладка — доли:** `fr`, `%`, `minmax()`, токены. Фиксированных px в ширинах
   колонок и текстовых блоков не остаётся.
3. **Декор и абсолютные слои — `cqw`** от `.container` (см. ниже).

**Токены в `base.css`** (все — кусочно-линейные, точно попадают в макет на 1200/1600/1920):
`--fs-h1/h2/h3/h4/btn/text/small`, `--page-gap`, `--gap-cards`, `--card-pad`,
`--radius-btn`, `--radius-card`.
Формула читается так: `max(<отрезок 1200→1600>, <отрезок 1600→1920>)` в `clamp()`;
`max` работает как кусочная функция, потому что кривая выпуклая. Там, где наклон
падает (hero: поле 30→50→60, высота 540→674→790 — потолок поднят с 695, а пол
с 470 до 540, оба раза ради зазора «стикер → инфо-карточки», см. `hero.css`),
кривая вогнутая и берётся `min()`.

**Боковое поле страницы — только через `--page-gap`** (10 на ≤1600, 20 на 1920).
Хардкодить `20px`/`10px` в секциях нельзя.
**Внутреннее поле карточек-секций — `--card-pad`** (20 на ≤1600 → 60 на 1920;
замер подтверждён дважды: аттестат `1:22943` и «классы» `1:23578`).
Исключение: **шапка не следует `--page-gap`** — у неё собственный padding
`16px 30px 16px 20px`, одинаковый на 1920/1600/1200, задан в `header.css` явно.

**`container-type: inline-size` объявлен один раз** — в `layout.css` на
`main .container, footer .container`. Поэтому `1cqw` в любом блоке = 1% ширины его
карточки-секции на любой ширине экрана.
⚠️ **Не вешать его на `body` и на контейнер шапки:** containment создаёт блок
позиционирования для `position: fixed`, и мобильное меню (`.header__menu`)
перестало бы раскрываться на весь экран. Лайтбокс и модалка формы лежат в `<body>`
вне `main` — их это правило не задевает.

**Канон брейкпоинтов — четыре:** `1280` (двухколоночные блоки в столбик),
`1024` (планшетные раскладки), `768` (точечно, только `programs` и `staff`),
`767` (телефоны) + один по высоте `max-height: 860px` (модалка формы).
Ступени 1600 / 1400 / 1279 / 1200 / 1100 / 900 / 560 / 480 удалены — их работу
делают токены. **Новую ступень заводить только если меняется раскладка,
а не масштаб.**

⚠️ **Высоты не фиксируем.** Все `min-height` — резиновые (в `cqw` с полом):
при переливе текста блок должен расти, а не обрезать содержимое. Так сделано
у hero, инфо-карточек, аттестата, педсостава, бенто факультативов, персонала, тарифов.

**Ловушки при переносе декора и подсветок из Figma** (на все уже наступали):
1. **`cqw` считается от content-box контейнера.** Вешать `container-type: inline-size`
   на карточку с `padding: 60` нельзя — единица станет 1760/100 вместо 1880/100, и весь
   декор уедет влево и смельчает на 6%. Вешать на обёртку без внутренних отступов
   (`.container`): её content-box равен ширине карточки на всех брейкпоинтах.
   ✅ **Закрыто 21.07.2026 глобально:** `container-type` объявлен один раз в `layout.css`
   на `main .container, footer .container`, локальные объявления из блоков убраны.
   Ошибка в `universities.css` (контейнер висел на карточке с `padding: 60`) исправлена,
   значения волны пересчитаны с базы 1760 на 1880 (×0.93617). Это было не косметикой:
   `--card-pad` теперь резиновый, доля content-box менялась бы с шириной экрана
   и подогнанный «под неверную базу» декор поехал бы.
2. **`backdrop-filter` на многострочной подсветке-маркере не применять**, хотя в Figma
   у плашек стоит `blur(20)`. У инлайна, разорванного на строки, браузер берёт общий бокс
   всех строк, и блюр съедает соседний текст. Плюс в Figma плашки лежат **под** текстом,
   а фон инлайна красится **поверх** уже отрисованных строк — поэтому и вертикальный
   padding маркеру не задаём (в макете плашка 49 при строке 43.2 и наезжает на соседнюю).
3. **Габаритам и повороту декор-нод из Figma верить нельзя — позицию подбирать по `1920.png`.**
   На вихре FAQ (`1:5931`) API отдавал `rotation: −150°` и AABB 2428.43×2105.55 в точке
   (−921, −143) от карточки, а экспорт пришёл 2175×994. Причина: экспорт отдаётся **уже
   в финальной ориентации** (поворот применён) и **обрезанным по краске**, поэтому ни
   размер, ни точка из API к нему не подходят — арифметика на них не сходится ни при
   каком угле. Рабочий способ: экспортировать PNG, наложить на вырезку из `1920.png`
   и подобрать сдвиг/масштаб численно (минимум RMSE по зоне, не перекрытой контентом).
   Для FAQ вышло: **без поворота, масштаб 1:1, сдвиг −746 / +514**.
4. **Крупному декору обязателен `max-width: none`.** В `base.css` глобально стоит
   `img { max-width: 100% }`; вихрь шириной 115cqw (2175px) без этого схлопывается
   до ширины карточки. Есть в `faq.css`, `no-homework.css` и `ege-banner.css` —
   проверено 21.07.2026, пункт закрыт.

**Мобильный проход 360–767 сделан по всем живым блокам (20.07.2026).** Единый брейкпоинт —
`@media (max-width: 767px)`; в диапазоне 561–767 «полудесктопных» состояний больше нет.
Старые 560/600/480/375 убраны. `pricing.css` и `reviews.css` (блоки закомментированы

**Грабли, на которые наступили при мобильном проходе (сверка в Playwright, 20.07.2026):**
1. **`max-width: none` крупному декору — не «желательно», а обязательно.** Без него
   глобальное `img { max-width: 100% }` режет вихрь «нет ДЗ» (1224 → 360) и детей
   в «Приглашении» (461 → 320); декор либо уезжает за экран, либо обрезается.
   Проверять каждый `<img>`, у которого ширина больше 100% контейнера.
2. **`justify-items: center` + `aspect-ratio` + `loading="lazy"` = схлопывание.** Пока
   картинка не загружена, её ширина 0, ячейка обнимает её, aspect-ratio даёт высоту 0 —
   блок логотипов вузов складывался в 20px и прыгал при догрузке. Нужен `justify-items: stretch`.
3. **Диагональный градиент `135deg` вырождается на узких высоких секциях.** На 360×1676
   («Выберите класс») переход укладывается в верхний угол и даёт тёмное пятно.
   Для таких блоков — `--gradient-accent-v`.
4. **`object-fit: cover` на широком декоре в высокой секции раздувает его в разы.**
   У «Классов» пришлось прижать вихрь к низу через `contain`.
5. **Скрывать `<br>` через `display: none` нельзя** — слова слипаются (пробела вокруг
   переноса в разметке нет). Убирать сам `<br>`, а перенос на десктопе задавать `max-width`.
6. **Проверяя правки в браузере, сбрасывать кеш CSS** (перевесить `href` у `<link>`
   с уникальным параметром): при быстрых повторных правках одного файла Playwright
   отдаёт старую версию, и «фикс не сработал» оказывается ложной тревогой.

**Блокировка страницы под модалками — `lockScroll()` / `unlockScroll()` из `main.js`**
(используют форма и лайтбокс). Три грабли, все три собрали:
1. Одного `body { overflow: hidden }` мало — на телефоне страница «пробивается» свайпом.
   Поэтому body ещё и `position: fixed` со смещением `top: -<позиция>`, иначе он прыгает в начало.
2. **После снятия `position: fixed` нельзя сразу звать `scrollTo`** — пока body был вне потока,
   высота документа схлопывалась до экрана (12922 → 691), и браузер обрезал значение до 0.
   Нужен принудительный пересчёт: `void document.body.offsetHeight`.
3. **Возврат позиции только `behavior: 'instant'`** — у `html` стоит `scroll-behavior: smooth`
   (плавные якоря), и обычный `scrollTo` возвращает позицию анимацией: страница после закрытия
   пару секунд едет от начала. Именно это выглядело как «позиция не восстанавливается».
- Скролл-контейнерам оверлеев — `overscroll-behavior: **none**`, а не `contain`: `contain`
  гасит только прокрутку страницы под модалкой, но оставляет «резинку» — ленту можно
  оттянуть за край, и в зазоре видно страницу.
- **Подложке модалки — `position: fixed`, а не `absolute`.** Контейнер прокручивается,
  и абсолютная подложка ехала бы вместе с контентом, открывая страницу за краем.
- На телефоне форма во весь экран, затемнение не видно: подложка там скрыта, а контейнер

### JS
- Vanilla JS, ES2015+, без зависимостей. Один файл = один блок; данные блока (расписания, сотрудники, FAQ) — обычные массивы/объекты в начале его JS-файла, рендер в DOM.
- Каждый файл самодостаточен: находит свой корневой элемент по классу блока, если его нет на странице — тихо выходит.
- Никаких глобальных переменных, кроме явно общих хелперов из `main.js` (например, `openForm()` — все CTA страницы ведут на форму).

### Типографика текстов (проход 21.07.2026)

Весь видимый текст набран по нормам: неразрывный пробел после коротких предлогов
и союзов, между числом и словом («2 дня», «стаж 35 лет»), в сокращениях
(«гос. образца», «уч. год», «№ Л035-…»), **перед** длинным тире и в разрядах чисел
(«25 000»). Тире в предложении — `—`, диапазоны — `–` («1–4 класс», «9:00–9:20»),
кавычки — только «ёлочки». Название школы везде **«Моя школа LS»** («школа» со
строчной), в кавычках, когда это имя собственное. Тексты ёфицированы.
Новый текст добавляем сразу по этим правилам.

⚠️ **Где какой символ:**
- в `index.html` — сущность `&nbsp;`;
- **в данных JS — литеральный U+00A0**, а не сущность: часть строк вставляется через
  `textContent` (заголовок таба в `attestat.js`, ответ в `faq.js`, имя и бейджи
  в `staff.js`, распорядок в `programs.js`), и `&nbsp;` там вывелась бы как текст.
  В редакторе такой пробел неотличим от обычного — в шапках этих файлов стоят
  предупреждения.

⚠️ **Геометрия важнее идеального nbsp.** Неразрывный пробел меняет точку переноса,
и в пиксель-выверенных блоках лишняя строка ломает не только текст (у FAQ от высоты
айтемов зависит положение вихря). Пять неразрывных пришлось вернуть на обычный пробел
— каждое место помечено комментарием в коде, список и замеры в `PLAN.md`.
Ставя новый nbsp в узкой колонке, проверять высоту блока на 1280 и 375.

`p { text-wrap: pretty }` в `base.css` снимает висячее слово в конце абзаца.
**Заголовкам `text-wrap` не давать** — у них переносы расставлены вручную `<br>` по макету.

### Изображения
- Раскладка: `assets/img/<блок>/…` (например `assets/img/hero/kids.png`).
- Пока клиент не прислал экспорты — фоны и вырезки временно резать из `1920.png`; в имени файла помечать `-tmp` и заменять по мере поступления.
- Фоны и крупные растровые — конвертировать в WebP; всё ниже первого экрана — `loading="lazy"` (+ `decoding="async"`, чтобы декодирование не подтормаживало прокрутку).
- Инлайн-SVG не генерировать руками, кроме мелких иконок (шевроны, стрелки, галки).

**Ленивая загрузка (проход 07.08.2026).** В разметке `loading="lazy" decoding="async"`
стоит у всех картинок, **кроме первого экрана**: лого шапки, пины/искры и вырезки детей
в hero остаются жадными — они и так видны сразу, а lazy отложил бы отрисовку и просадил LCP.
(В офлайн-папке здесь была отдельная оговорка про генератор второго города —
в онлайн-версии генератора нет, вся разметка живёт прямо в `index.html`.)

⚠️ **Картинкам, которые создаёт JS, атрибута мало — им нужен `window.applyLazySrc()`
из `main.js`** (постеры отзывов, постеры обзорных роликов, миниатюры педагогов).
Такая картинка создаётся с `data-src` вместо `src`, а после вставки в DOM блок зовёт
`window.applyLazySrc(контейнер)` — дальше `IntersectionObserver` подставляет настоящий
`src`, когда до картинки доскроллили. Почему не нативный механизм: блоки рендерятся
defer-скриптами, то есть **до первой отрисовки**, и браузер в этот момент ещё не знает
координат элемента — откладывать ему нечего, и он грузит сразу. Замер на локальном
сервере: постеры отзывов лежат на 7000px ниже экрана, а запрашивались все 15 на 166-й мс;
не помогли ни порядок атрибутов (`loading` перед `src`), ни отсрочка на `requestAnimationFrame`
с принудительным пересчётом макета. ℹ️ На боевом домене нативный lazy эти же постеры
откладывал — там сеть медленнее и макет успевает построиться. То есть срабатывание
зависело от гонки «разбор HTML против первого layout»: быстрая отдача статики
(CDN, повторный визит с прогретым кешем) — и 880 КБ уходили впустую. Наблюдатель
убирает эту зависимость. `rootMargin: '400px 1600px'` — вертикаль с запасом на подгрузку,
горизонталь готовит соседнюю страницу пагинатора, иначе плитки моргали бы пустотой
при листании стрелкой.

## Деплой (FTP)

⚠️ **Своего сервера у онлайн-версии пока НЕТ, автозаливка выключена.**
В `.vscode/sftp.json` лежат доступы **офлайн-сайта** (`92.255.104.226:21`, ProFTPD,
пользователь `agb`, корень `/`) и стоит `uploadOnSave: false` — с включённой заливкой
первое же сохранение затёрло бы живой agb.lancmanschool.com онлайн-версией.
Получите креды площадки онлайн-школы, подставьте их и верните `uploadOnSave: true`.
Всё, что ниже в этом разделе, описывает боевой сервер офлайн-сайта и пригодится,
когда онлайн-версию поднимут на такой же площадке. **Список исключений**
(что НЕ заливается) в `sftp.json` актуален и для этой папки.

⚠️ **Сервер за NAT — простой пассивный FTP не работает.** На команду `PASV` ProFTPD
отдаёт **внутренний** адрес, недоступный снаружи, и data-соединение сбрасывается
(`Connection reset by peer` / таймаут). Голый `ftplib`/`curl` в пассивном режиме падает
на первом же файле. Два рабочих обхода:
- **игнорировать адрес из `PASV` и брать IP управляющего соединения** — так делает плагин
  и мой скрипт заливки (`class FTP(ftplib.FTP): makepasv → self.sock.getpeername()[0]`);
- либо **активный режим** (`PORT`/`set_pasv(False)`), если клиент открыт со стороны сети.

ℹ️ Асимметрия NAT: **загрузка (`STOR`) проходит, скачивание (`RETR`) рвётся** тем же NAT.
Поэтому проверять деплой скачиванием по FTP ненадёжно; факт заливки подтверждает ответ
сервера `226` на `STOR`. Живую страницу смотреть по HTTP уже под доменом (по «голому» IP
отдаётся дефолтный хост, не наш сайт).

⚠️ **Сайт стоит за DDoS-Guard, и статика кешируется на сутки** (обнаружено 31.07.2026 при проверке заливки): ответ на `https://agb.lancmanschool.com/css/invite.css` приходит с `server: ddos-guard`, `cache-control: max-age=86400` и ненулевым `age`. Сразу после заливки по «голому» URL ещё несколько часов отдаётся **старая** копия, хотя на сервере уже новая (FTP `SIZE` показывает новый размер — по нему и надо сверять факт заливки). URL с параметром — **другой ключ кеша**, поэтому `css/invite.css?v=5` отдаёт свежий файл сразу. Отсюда практический вывод: **проверять деплой надо по тому URL, который реально запрашивает браузер (с `?v=`)**, а бампать `?v=` при каждой правке CSS/JS обязательно — без этого правка не доедет до пользователей ещё сутки.

### Фавиконка — диагностика 08.08.2026 (жалоба «в браузерах нет фавиконки»)

**Дефекта не нашлось, вёрстка и файлы исправны — заново эту цепочку не проходить.**
Что проверено на боевом домене: все 5 тегов в `<head>` отдаются живой страницей; все файлы
(корневые и `assets/favicon/*`) — HTTP 200 с верными content-type; md5 прода совпадает
с локальными побайтово; `robots.txt` ничего не закрывает; YandexBot, Googlebot и запрос
без UA получают 200. Решающая проверка — **Chrome с чистого профиля**: он сам скачал
`favicon.ico`, декодировал и положил битмапы 16×16 и 32×32 в свою базу `Favicons`
(она лежит в `<профиль>/Default/Favicons`, обычная SQLite — таблицы `favicons`,
`favicon_bitmaps`, `icon_mapping`). **Это лучший способ доказать, что иконка реально
доезжает до браузера,** скриншот вкладки снять нельзя: Playwright не фотографирует UI
браузера, а `screencapture` на этой машине без разрешения на запись экрана не работает.

⚠️ **Состояние Яндекса проверяется через `favicon.yandex.net/favicon/v2/<домен>?size=32`.**
Для `agb.lancmanschool.com` там уже лежит наш розовый ромб. Контроль обязателен: для
несуществующего домена сервис отдаёт **пустой пиксель 1×1 (70 байт)**, а не 404, — без
этой сверки «200 OK» ничего не доказывает. Глобус в выдаче на скриншоте клиента —
состояние до обхода робота либо кеш его собственного браузера (фавиконки кешируются
цепко, Ctrl+F5 их не сбрасывает — проверять в инкогнито). **Выдачу Яндекса в Playwright
воспроизводить бесполезно:** в автоматизированной сессии иконок нет ни у кого,
включая конкурентов, у которых на скриншоте они есть.

### Манифест: `purpose` иконок — починено 08.08.2026

⚠️ **Было:** обе иконки в `site.webmanifest` помечены только `purpose: "maskable"`.
Из-за этого **сайт не проходил установочные критерии PWA** — Chrome отдавал
`manifest-missing-suitable-icon` и `no-acceptable-icon` (нужна иконка ≥144px с
назначением **`any`**; `maskable`-only эту проверку не удовлетворяет, наличие 192 и 512
не помогает). **Стало:** `"purpose": "any maskable"` у обеих. Новые ассеты не рисовали —
у иконок уже есть корректные поля, они годятся и как `any`.
⚠️ **У ссылки на манифест есть версия — `site.webmanifest?v=2`**.
Без неё правка манифеста пролежала бы за кешем DDoS-Guard сутки и факт заливки нечем было бы
проверить. **Правите манифест — поднимайте `?v=`** в `index.html`.

⚠️ **Сами иконки перерисовывать НЕ надо — они собраны правильно.** Легко ошибиться:
логотип занимает 60% рамки, поля по 38px при 192 (нужно ≥19), дальняя точка краски —
радиус 57.9 при безопасном 76.8, фон непрозрачный белый. **Границы логотипа мерить
по небелым пикселям, а не по альфе:** фон непрозрачный, поэтому замер по альфе даёт
«краска на всю рамку» и ложный вывод, что полей нет (на этом уже споткнулись).

**Как проверять установочные критерии** (единственный надёжный способ, глазами не видно):
CDP-команда `Page.getInstallabilityErrors` через Playwright. Готовые скрипты сессии —
в scratchpad, схема простая: `chromium.launch({ executablePath: '/Applications/Google
Chrome.app/…/Google Chrome' })` — браузеры в `~/Library/Caches/ms-playwright` отстают
от версии пакета в npx-кеше, поэтому берём системный Chrome; `newCDPSession` →
`Page.enable` → `goto` → пауза ~2.5с → `getInstallabilityErrors`. Ошибку `in-incognito`
отфильтровать — это артефакт автоматизации. ⚠️ `Page.getAppManifest` для этого
**не годится**: он показывает только ошибки парсинга и на этом дефекте молчал (пусто).

ℹ️ **`Content-Type` у `.webmanifest` пустой** вместо `application/manifest+json` —
оставлено как есть **осознанно**. Chrome манифест принимает и парсит без ошибок
(контрольный тест: на локальном сервере с *правильным* заголовком возврат к
`maskable`-only всё равно ломал установку — значит заголовок ни на что не влиял).
Чинится только через `.htaccess` с `AddType`, а при `AllowOverride`, не допускающем
`FileInfo`, Apache отвечает **500 на весь сайт**. Риск положить боевой сайт ради
молчания валидатора не оправдан.

## Проверка

✅ **Playwright разрешён свободно (решение клиента 21.07.2026)** — прежний запрет «не проверять
после каждой доработки» снят. Любую правку вёрстки можно и нужно перепроверять в браузере:
замерить геометрию через `getBoundingClientRect()`, прокликать состояния, снять скриншот.
Для правок, не влияющих на отрисовку (тексты в данных, комментарии, переименования),
прогон по-прежнему необязателен — но это выбор по существу, а не экономия лимитов.

**Как запускать (проверено 21.07.2026):**
- MCP-браузер режет протокол `file://` — поднимать локальный сервер:
  `python3 -m http.server 8765` в корне `school/`, открывать `http://localhost:8765/index.html`.
- Если MCP отвечает `Browser is already in use … mcp-chrome-<hash>` — в системе висит
  осиротевший инстанс с прошлой сессии. Найти его `pgrep -f mcp-chrome-<hash>` и снять
  `kill <pid>` (это автоматизационный профиль, не личный Chrome пользователя).
- Скриншоты Playwright по умолчанию падают в корень проекта (`.playwright-mcp/` и файлы
  рядом с `index.html`) — после проверки удалять.
- ⚠️ **Кеш.** Параметр в адресе (`index.html?v=2`) обновляет только саму страницу — CSS и JS
  подтягиваются из кеша по прежним URL, и правка «не работает». Для CSS помогает перевесить
  `href` у `<link>`, но **для JS этого приёма нет**: повторная вставка `<script>` запускает
  IIFE второй раз (дублируются обработчики и созданный из JS подзаголовок — замеры высоты
  сразу врут). Надёжный способ — поднимать сервер, который сам запрещает кеш:
  `SimpleHTTPRequestHandler` + `Cache-Control: no-store` в `end_headers`. Если старая версия
  уже осела в кеше, вытолкнуть её: `fetch('js/attestat.js', { cache: 'reload' })`, затем
  перезагрузить страницу.

- **Playwright** (MCP-инструменты доступны): скриншоты на ширинах **1920 / 1280 / 768 / 375**, визуально сверить с `1920.png` и мобильными макетами из `фото тз/`.
